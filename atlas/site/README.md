# Atlas static site

Static, data-generated site for **Commonworld Atlas**, built to live at `https://commonworld.one/atlas/`.
Zero dependencies: the generator, the local server and the checks are plain Python 3.9+ (standard library only).

- Input data: `atlas/data/snapshot-verified-2026-10-15.json` (only published cards; the review queue is never published).
- Output: `atlas/site/dist/` (not committed; build it with one command). The same folder deploys unchanged to Cloudflare.

## Run locally (macOS)

Open Terminal and paste, line by line:

```bash
# 1. get the code (skip the clone line if you already have the repo)
git clone https://github.com/commonworld-one/commonworld.git
cd commonworld
git pull

# 2. optional but recommended: Pillow for per-page Open Graph images (listed in requirements.txt at the repo root)
python3 -m pip install -r requirements.txt

# 3. build the site into atlas/site/dist/  (add --local to point the "Commonworld" links at / instead of https://commonworld.one/)
python3 atlas/site/build.py

# 4. optional: run the checks (links, titles, canonical, JSON-LD, sitemap, page size)
python3 atlas/site/check.py

# 5. start the local server, then open the Atlas in the browser
python3 atlas/site/serve.py
```

Then open <http://localhost:8080/atlas/> (or run `open http://localhost:8080/atlas/` in a second Terminal tab). Stop the server with `Ctrl+C`.
Another port: `python3 atlas/site/serve.py 9000`.

`python3` ships with the Xcode Command Line Tools; if macOS asks to install them, accept and re-run the command.
`serve.py` behaves like Cloudflare Pages: clean directory URLs, `/atlas/about` → 301 → `/atlas/about/`, real 404 status with `404.html`. Locally only, `/` redirects to `/atlas/` (the Commonworld home is a placeholder for now).

## Design system (`components/`)

The visual system is the Commonworld catalog draft (`research/atlas/catalog_en.html`): Inter/system font stack, warm paper
palette (`--bg #f4f1ea`, `--paper #fbfaf7`, `--ink #202522`, accent `#e75b3d`), 14–18 px radii, 1 px hairlines, tiny uppercase
labels, huge tight headlines; light and dark themes. It lives in three framework-free files meant to be reused by the whole
Commonworld product:

- `cw-components.css` — tokens (both themes) and every shared block: shell + sidebar (drawer under 900 px; above 900 px it can be
  hidden with the top-row **Hide sidebar / Show sidebar** button, class `cw-side-off` on `<html>`), top row with icon
  buttons, stats strip tiles, colored category bar + legend, hero + info box, pill tabs, panel + filter bar, **tag shelf**
  (“козырек”: the clipped row of `#tag N` chips with the `all tags (N) ↓` expander and the hint line), cards (2 columns, 1 on
  mobile), status/type chips, ad slots, native ad card, announcement bar, consent banner, footer, breadcrumbs.
- `cw_components.py` — HTML for the same blocks (`sidebar`, `top_row`, `stats_strip`, `catbar`, `legend`, `hero`, `info_box`,
  `tabs`, `tag_shelf`, `tag_chips`, `card`, `ad_card`, `ad_slot`, `announcement_bar`, `consent_banner`, …). No Atlas data inside.
- `cw-components.js` — theme toggle, announcement dismissal, consent + GA4 loader, drawer, sidebar hide/show (`cw_components.side_toggle()`,
  `aria-expanded`/`aria-controls="cw-side"`, label follows state; stored in localStorage `cw-side`), search clear + `/` shortcut, tag shelf
  expander (`el.cwRefresh()` after changing chips). Chips cut off by the collapsed shelf or covered by the expander are made `inert`
  (not focusable or tappable; WCAG 2.5.8), re-fitted on resize, load and `document.fonts.ready`.
- Accessibility floor: counters in pills, tabs and tag chips use full `--muted` (≥ 4.5:1, no opacity fade); footer links and
  Cookie settings are ≥ 24×24 px tap targets. `check.py` and `smoke_test.py` assert both.

Two deliberate departures from the draft: light-mode `--muted`/`--accent-text` are a shade darker so small text passes WCAG AA,
and the theme lives on `<html data-theme>` (set before paint) instead of `body.dark`. Category colors come from `CATEGORIES` in
`build.py` (the draft's palette; `projects` got teal `#5f9ea0`) and are emitted as `.k-<category>` classes.

## Tags

The `#tags` on cards and in the tag shelf are **descriptive labels from the 2026-10-15 census** (the same tags as
`research/atlas/catalog_en.html`), **not verified claims**. `tools/extract_census_tags.py` maps them onto the published entries
by census id (checked against name / canonical host), lowercases them, drops internal/status/judgement tags (`dead`, `dormant`,
`quiet`, `unverified`, `not-deep-dived`, `*-listed`, `fake`, `stale`, …), merges duplicates (`oss` → `open-source`,
`games` → `game`, …) and keeps only tags used by at least two published entries. Re-run it after the census or snapshot changes.

## Announcement bar and ad slots (`site-config.json`)

Both are reusable components in `components/cw_components.py` (HTML), `components/cw-components.css` and `components/cw-components.js`. They have no Atlas-specific code, so the main Commonworld product can import the same three files and the same config shape.

**Announcement bar** (top of every page):

```json
"announcement": {
  "enabled": true,
  "id": "atlas-first-release-2026-10",
  "text": "Atlas first release: every card is checked against its own sources before it is published.",
  "link": { "href": "/atlas/about/", "label": "How we verify" }
}
```

- `enabled: false` hides it. `link` is optional (external links get `rel="nofollow noopener"`).
- Visitors can dismiss it; the dismissal is stored per `id` in localStorage and applied before first paint (no flash).
- **New message → change the `id`** (e.g. add a date), otherwise visitors who dismissed the old one won't see it.

**Ad slots** (named; each page template calls the slot it owns):

| Slot name | Where | Default size |
| --- | --- | --- |
| `atlas-index-top` | Atlas index, under the hero, above the catalog (full width) | 728×90 reserved height |
| `atlas-native-card` | Catalog grid (index + category pages): a card in the same style after every 12 visible cards; re-inserted when filters/search change. Creative: `href`, `title`, `text` | card |
| `atlas-sidebar` | Bottom of the left navigation (where the draft had its "Draft" box; inside the drawer on mobile) | 210×120 |
| `atlas-category-top` | Category pages, under the header | 728×90 |
| `atlas-platform-top` | Card (platform) pages, under the header block (title, status, description, info box), above the verified facts; same banner as `atlas-index-top` | 728×90 |
| `cw-stats-top` | Stats page (`/stats/`), under the header, above the first section; same banner as `atlas-category-top` | 728×90 |

```json
"atlas-index-top": {
  "enabled": true,
  "size": [728, 90],
  "placeholder": true,
  "creative": { "href": "https://sponsor.example", "title": "Sponsor", "text": "One line", "image": "/atlas/assets/ads/sponsor-728x90.png", "alt": "Sponsor" }
}
```

- `enabled: false` → nothing is rendered.
- `creative: null` + `placeholder: true` → a neutral "Sponsored · Your ad here" box (native card: "Your project here") linking to `/atlas/about/#advertise`; `placeholder: false` → nothing. All sponsored links carry `rel="sponsored nofollow"`.
- With a `creative`, the link gets `rel="sponsored nofollow noopener"`; `image` is optional (text-only creative otherwise). Put image files in `atlas/site/static/` (copied to `/atlas/assets/`; only `.png/.ico/.svg` are copied — extend `build.py` for other types).
- `size` is reserved with CSS before anything loads, so the layout never shifts.
- In a template: `cw.ad_slot(site.cfg, "slot-name")`. New slot = add it to the config and call it where it should appear.

After changing the config: `python3 atlas/site/build.py` again.

## Open Graph images (per page)

Every indexable page gets its own 1200×630 share image at `/atlas/og/<name>.png` (platform pages: `<slug>.png`; categories:
`category-<cat>.png`; index: `atlas.png`; other pages: `page-<name>.png`), in the light Atlas style: CW logo + "Atlas", category
chip and color bar, name, live/closed + type + number of verified claims, one short description, `commonworld.one/atlas`, verified
date. Pages set `og:image` (with `?v=<hash>` so social caches refresh when a card changes), `og:image:width/height/alt`,
`twitter:card=summary_large_image`, `twitter:image(:alt)`.

- Renderer: `og_images.py` (needs **Pillow**: `pip install Pillow`; the rest of the build stays stdlib). Palette PNGs, ~22 KB each.
- Cached in `atlas/site/.og-cache/` (gitignored) by a hash of the page's spec + fonts + logo: the first build renders all images
  (~30 s), later builds copy unchanged ones (<1 s). Same input gives byte-identical files. Change `RENDER_VERSION` to force a re-render.
- Fonts: Inter if installed, else Liberation Sans / Arial / DejaVu Sans.
- Without Pillow the build still works and every page falls back to `static/og-atlas.png` (with a warning); `check.py` then fails
  on purpose, because images are no longer unique per page. The repo-root `requirements.txt` (`Pillow>=10`) covers Cloudflare Pages.

## Homepage screenshots (`screens.py`)

The screenshots are **not stored on `main`**. They live on the orphan branch `atlas-screens` of this repo, which holds only
`atlas/screens/<slug>.webp` (1200×750 WebP, one 1280×800 viewport of the public homepage, no login) and `atlas/screens/manifest.json`
(per slug: file, sha256, dhash, website, source_url, http_status, title, captured_at UTC, width, height, bytes). History stays on that
branch; it never merges into `main`.

- `build.py` calls `screens.load()`: `CW_SCREENS=off` disables previews; `CW_SCREENS_DIR=/path` uses a local folder (manifest.json +
  `<slug>.webp`); otherwise the `atlas-screens` commit pinned in `atlas/screens.lock` (one line, full 40-hex sha; `CW_SCREENS_SHA=<sha>`
  overrides it, `CW_SCREENS_SHA=head` follows the branch head for local work) is fetched by sha (`--depth=1` in shallow clones) and
  `git archive`d into `atlas/site/.screens-cache/branch/` (gitignored), with the public tarball of that commit from codeload.github.com
  as fallback (Cloudflare Pages only clones the branch it builds). Files with a wrong sha256, size or non-https source are skipped
  with a warning. After a weekly screenshots PR is merged into `atlas-screens`, a PR on `main` bumps `atlas/screens.lock`.
- Nothing found → the build still succeeds and every card shows a placeholder. CI sets `CW_SCREENS_REQUIRED=1`, which makes that an error.
- Output: `dist/atlas/screens/<slug>.webp`, `dist/atlas/screens/t/<slug>.webp` (600×250 top band, Pillow, cached by sha256 in
  `.screens-cache/thumbs/`; without Pillow the grids reuse the full image), `dist/atlas/screens/manifest.json`, and a `preview` field
  (path, url, thumb_url, width, height, captured_at, source_url, rights; or null) on every record in `platforms.json`,
  `platforms/<id>.json`, `categories/<k>.json` and `/api/v1/` (schema_version 1.1.0). The GitHub mirror `atlas/public/` leaves `preview`
  out on purpose, so a new screenshot never makes the committed mirror stale.
- Layout: catalog grids show the top band of the screenshot as a decorative thumbnail (`alt=""`, the card title names it); the card
  page shows the full 8:5 screenshot with a dated caption, directly under the header and the sponsored slot, above the facts. Closed
  cards keep their last capture ("Last captured …", greyed). No og:image change: share cards stay the generated OG images.
- `check.py` checks files, sizes (screenshot ≤ 256 KB, thumbnail ≤ 25 KB), manifest/preview drift, orphans, that no branch image of a
  published card was dropped, the card-page order and markup, grid thumbnails and the `_headers` cache rule.
- Capture rules for new screenshots: homepage only, honest bot User-Agent (`CommonworldAtlasBot/1.0 (+https://commonworld.one/atlas/about/)`,
  as in `atlas/refresh.py`), cookie banners/modals hidden, network idle + a few seconds with animations off, every new image compared
  with the previous one before it replaces it, failed or empty captures never published (placeholder instead). Commit new images to
  `atlas-screens` only, never to `main`.
- Rights: third-party content, not CC BY (see `LICENSE-DATA.md` and `/atlas/about/#screenshots`); removal on request via the corrections link.

## Share buttons (`site-config.json` → `share`)

`cw.share_bar(cfg, canonical_url, text)` in `components/` (reusable in the main product). Shown on every platform page **in the header
card, next to the Visit button** (compact icon row, `cls='cw-share-head'`, so visitors can share on landing; once per page) and on the
Atlas index (under the hero). Buttons: X, LinkedIn, Telegram, Reddit, Facebook, Email, Copy link,
plus a native **Share** button (Web Share API) that appears only on touch devices whose browser supports it. Share text (+ the canonical URL)
depends on the page: entry pages by status, `<Name> — verified on Commonworld Atlas` (verified), `<Name> on Commonworld Atlas` (listed),
`<Name> (closed) — history on Commonworld Atlas` (closed); index `Atlas of Agent Platforms: <N> places where AI agents work and get paid`
(N = live entries); earn view `Where AI agents get paid — Commonworld Atlas`.

```json
"share": { "enabled": true, "label": "Share", "native": true, "networks": ["x", "linkedin", "telegram", "reddit", "facebook", "email", "copy"] }
```

- Plain share-intent links (`rel="nofollow noopener noreferrer"`, new tab); no third-party scripts, no tracking pixels.
- Inline SVG icons in `currentColor` (light/dark), 36 px round buttons (40 px on phones), aria-labels, keyboard operable; "Copied"
  is announced through an `aria-live` status.
- Analytics: a GA4 `share` event (`method` = x / linkedin / telegram / reddit / facebook / email / copy / native) is sent only if
  the visitor accepted analytics cookies; nothing otherwise.
- Key events (GA4, same consent rule, in `static/atlas.js`): `visit_platform` (Visit button on a card; `item_id` = card ID,
  `link_domain`), `badge_copy` (Copy on a badge snippet; `format` = html / md / link), `api_use` (`method` = copy for the
  API page examples, open for a click on an `/api/v1/…json` link). Mark them as key events in GA4 Admin → Events.
  Agents usually do not run JavaScript, so agent traffic is measured from Cloudflare, not GA4.

## Theme, analytics, consent

- Light theme by default for first-time visitors (`site.default_theme`, `light` or `dark`), dark theme via the sun/moon icon button; the choice is stored in localStorage (`cw-theme`). An inline head script sets the theme before first paint (no flash).
- Sidebar hide/show (desktop, > 900 px): stored in localStorage (`cw-side` = `off`; removed when shown again). The same inline head script adds `cw-side-off` to `<html>` before first paint, so a hidden sidebar never flashes or shifts the layout. Listed in the Privacy Policy storage table and explained on /atlas/about/#navigation.
- GA4 `G-9QB65R36K6` (in `site-config.json` → `site.ga4_measurement_id`; empty string disables analytics and the banner).
  Google Consent Mode v2 defaults: everything denied. `gtag.js` is **not loaded** until the visitor clicks Accept; Accept grants `analytics_storage` only (ad storage stays denied). Reject is remembered; "Cookie settings" in the footer reopens the banner; switching from Accept to Reject deletes `_ga*` cookies.

## Deploy to Cloudflare (later)

Build command `python3 atlas/site/build.py`, output directory `atlas/site/dist`. The build fetches the screenshots itself (the `atlas-screens` commit pinned in `atlas/screens.lock`, via git, else the public tarball of that commit); Pages builds of the `atlas-screens` branch itself fail harmlessly (no build.py there) and can be excluded in the Pages branch settings. The repo-root `requirements.txt` (`Pillow>=10`) makes Cloudflare Pages install Pillow for the OG images. Pages serves `dist/atlas/...` at `/atlas/...`, uses `dist/404.html` for missing pages and applies `dist/_headers`. If `/atlas` is mounted inside a bigger Commonworld site, copy `dist/atlas/` into that site's output and merge `robots.txt` (it only has to contain the `Sitemap:` line for `https://commonworld.one/atlas/sitemap.xml`).

### Security headers and CSP

`build.py` writes `dist/_headers` with a strict Content Security Policy (no `'unsafe-inline'`). Rules for page code:
no `style=""` attributes and no inline `<style>` (add a class to `atlas.css`, or a generated class next to `color_classes` / `flex_classes` / `ad_slot_classes`), no `on…=""` handlers, no `javascript:` URLs.
An inline `<script>` is allowed automatically: `build.py` hashes every executable inline script it writes and puts the hash in `script-src`; `check.py` re-hashes every page and fails on anything missing.
Cloudflare injects its own inline JavaScript Detections bootstrap whose text changes per response; `functions/_middleware.js` (Pages Functions, HTML pages only via `dist/_routes.json`) adds a fresh per-request `'nonce-…'` to `script-src`, and Cloudflare stamps that nonce on what it injects. Since 2026-10-20 the live site is served by the platform Worker, which does the same for Atlas pages (`withAtlasNonce` in `platform/src/atlas-assets.ts`); the Pages Function only serves the Pages fallback. Our markup never uses the nonce.
`serve.py` sends the same headers (minus HSTS and `upgrade-insecure-requests`) and gzips text, so the smoke test and Lighthouse run under production rules.

## Link safety

Standard: [`TRUST.md`](../../TRUST.md). Atlas rules: [`atlas/CURATION.md#link-safety`](../CURATION.md#link-safety).

Every domain linked from the published Atlas (official URLs, claim and QA sources, any other URL in an entry, plus the
domains of removed entries) is checked every day by the Commonworld trust engine ([`trust/`](../../trust/)) against four
free sources: Google Safe Browsing, MetaMask eth-phishing-detect, ScamSniffer and the CERT Polska Warning List.
This gives every visitor and agent links that were checked within the last day, with each source's answer on the record.

- **How it runs.** `atlas/tools/link_safety.py --apply` (stdlib, uses the engine through Node 22.6+) is run by the workflow
  `.github/workflows/link-safety.yml` ("Atlas link safety") daily at 04:17 UTC and on demand. It writes
  `atlas/data/link-safety.json`: summary counts, `run_at`, and for every domain the answer of each source (verdict,
  `checked_at` in UTC, evidence link). If a source cannot answer this run, its previous answer for that domain is kept
  (marked stale), so a network error never hides an earlier flag.
- **What a status means.** `flagged` when any one source flags the domain, `clean` when at least one source answered
  and none flags it, `no_data` when no source could answer.
- **Auto-hide.** When any one source flags a domain, every entry that links to it is removed at once: the script records
  a decision in `atlas/data/removed.json` (actor `hark`, which source said what, evidence link) and drops the card from the
  snapshot and the census tags. The workflow then rebuilds and runs `check.py`; only when the check passes does it commit
  the data, the GitHub mirror (`atlas/public/`) and the report. If the check fails, it commits only the report and the issue
  says a curator step is needed. Domains listed in `atlas/data/trust-hold.json` are reported, not removed.
- **Issue and alert.** Any flag opens or updates the issue "Link safety: flagged domains" and fails the run (GitHub sends
  the failure email); a later clear run closes the issue.
- **Published.** The build turns the report into `/atlas/safety.json` and gives each record `link_safety` {status, checked_at}
  for its official URL; both are left out of the GitHub mirror because they change daily. Decisions are published at
  `/atlas/decisions/` (also `index.md` and `/atlas/decisions.json`).
- **Removed entries.** The slug keeps a neutral noindex stub ("This entry was removed from the Atlas after a safety check.",
  no name, no outbound link, not in the sitemap). Removed domains keep being checked daily; an entry returns only through a
  restore decision by a listed actor (`atlas/data/trust-roles.json`) with a clean re-check, never automatically.
- **Build check.** `check.py` accepts a removal only with its decision, a decision only from a listed actor, and a return only
  when the latest report shows the domain clean; it fails if the stub is missing or indexable, if any listing or data file
  still has the slug, or if any built file names the host.
- **Older script.** `atlas/tools/safebrowsing_check.py` is the earlier Google-only check; `link_safety.py` now reuses only its
  host extraction.
